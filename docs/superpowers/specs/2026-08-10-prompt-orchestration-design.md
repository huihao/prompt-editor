# 提示词拆分与编排设计

## 目标

用户在编辑器中写下单一提示词后，可以调用已配置的大模型，将其拆分并扩展为多个可编辑的提示词步骤。模型自动判断步骤依赖：不同阶段按顺序执行，同一阶段内的步骤标记为可并行。方案独立保存，不覆盖当前编辑器内容。本期只生成、编辑、保存和导出编排结构，不在编辑器内执行整条流程。

## 方案选择

采用“生成弹窗 + 编排方案管理器”。工具栏提供生成入口和已保存方案入口。生成结果在独立弹窗中编辑，避免影响现有 CodeMirror 状态、模板、历史和自动保存逻辑，同时保留未来接入执行引擎的结构化数据基础。

## 数据模型

```ts
interface PromptWorkflow {
  id: string;
  title: string;
  sourcePrompt: string;
  stages: PromptStage[];
  createdAt: number;
  updatedAt: number;
}

interface PromptStage {
  id: string;
  prompts: WorkflowPrompt[];
}

interface WorkflowPrompt {
  id: string;
  title: string;
  content: string;
}
```

阶段之间按顺序排列，同一阶段内的多个提示词表示并行组。每个步骤只有标题和完整提示词，暂不引入输入变量、输出变量或任意连线。

## 用户流程

1. 用户点击工具栏“提示词编排”按钮。
2. 有选区时使用选区内容，否则使用全文；内容为空时提示先输入。
3. 未配置 AI 时打开现有 AI 设置页。
4. 生成弹窗先展示原始提示词和生成状态，完成后展示可编辑阶段列表。
5. 用户可以编辑方案标题、阶段和步骤内容；拖动阶段改变顺序；在阶段间移动步骤改变串行/并行关系；新增、复制和删除阶段或步骤；取消、重试或重新生成。
6. 保存时写入独立的本地方案存储，关闭弹窗且不修改当前编辑器。
7. “编排方案”管理器列出已保存方案，支持继续编辑、重命名、复制全部和删除。复制全部生成易读 Markdown，按阶段编号并标注并行步骤。

## AI 生成协议

生成请求使用专用 system prompt，要求只返回符合协议的 JSON，不返回解释文字。协议核心为：

```json
{
  "title": "方案标题",
  "stages": [
    {
      "prompts": [
        { "title": "步骤标题", "content": "完整提示词" }
      ]
    }
  ]
}
```

请求使用现有 `streamAIText`。流式结果累积完成后剥离 Markdown 代码围栏并解析 JSON，再通过规范化函数生成稳定的本地 ID 和时间戳。生成弹窗支持取消；取消或失败时不保存半成品。

## 校验与容错

- 缺少标题、阶段或步骤内容时使用可识别的默认值补齐。
- 空阶段和空步骤自动移除。
- 步骤数量限制在合理上限，防止模型生成过大的方案。
- 无法解析的 JSON 显示格式错误并允许重试。
- 本地存储使用独立 key；读取时兼容空值、旧版本和损坏数据，损坏数据回退为空列表并保留当前编辑器内容。
- 删除方案需要确认；保存更新 `updatedAt`，并始终保留 `sourcePrompt`。

## 模块边界

- `prompt-orchestration.ts`：模型协议、生成调用、解析/规范化和 Markdown 导出。
- `prompt-workflow-store.ts`：本地方案的读写、增删改查和数据迁移。
- `prompt-orchestration-ui.ts`：生成弹窗与方案管理器的 DOM 交互、编辑、拖动和状态反馈。
- `editor.ts` / `index.html`：工具栏入口、弹窗宿主样式和事件接线。

模块复用 `ai-service.ts` 与 `ai-config.ts`，不新增 provider 配置，也不改变既有 AI Enhance 行为。

## 测试

- JSON 解析、代码围栏剥离、字段校验、默认值补齐、数量限制和 Markdown 导出。
- 阶段/步骤的新增、复制、删除、排序及跨阶段移动。
- 方案保存、读取、重命名、删除，以及损坏存储的恢复。
- AI 未配置、请求失败、取消请求和无效模型输出。
- 工具栏入口、弹窗关闭与保存后编辑器原文不变。

## 范围外

本期不执行步骤、不管理模型间的运行时上下文、不实现任意节点连线或变量绑定。数据模型保留后续加入执行能力的扩展空间。
